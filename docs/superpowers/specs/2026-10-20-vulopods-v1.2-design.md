# VuloPods v1.2 – Design

Datum: 2026-10-20
Basis: v1 und v1.1, alle Regeln daraus gelten weiter.
Umfang: Verbinden/Trennen im Tray, Einstellungsfenster mit Persistenz, Akku-Prozent im
Tray-Icon, Namespace-Umbenennung, Release-Paket. Weiterhin kein Treiber, kein Geräuschmodus.

## 1. Namespace `VuloPods.Core.System` → `VuloPods.Core.Platform`

Aus der v1.1-Review: Ein Namespace-Segment `System` überschattet `System.*` in künftigem
Core-Code. Ordner `src/VuloPods.Core/System` → `src/VuloPods.Core/Platform`, Namespace
überall angepasst (`AutostartManager`, `WindowsTheme`, alle `using`s in App und Tests).

## 2. Einstellungen

### Core

`src/VuloPods.Core/Settings/AppSettings.cs`:

```csharp
public enum TrayIconStyle { Logo, Percent }
public enum ThemeMode { System, Light, Dark }

public sealed record AppSettings
{
    public bool PopupOnLidOpen { get; init; } = true;
    public int PopupSeconds { get; init; } = 5;          // 3..15
    public bool AutoPause { get; init; } = true;
    public bool LowBatteryWarning { get; init; } = true;
    public int LowBatteryThreshold { get; init; } = 20;  // 10..50, Schritt 5
    public TrayIconStyle TrayIcon { get; init; } = TrayIconStyle.Percent;
    public ThemeMode Theme { get; init; } = ThemeMode.System;

    public AppSettings Normalized();  // klemmt PopupSeconds auf 3..15, Threshold auf 10..50 und rundet auf 5er-Schritte
}
```

Autostart ist **keine** gespeicherte Einstellung; die Wahrheit bleibt die Registry
(`AutostartManager`).

`src/VuloPods.Core/Settings/SettingsStore.cs`:

```csharp
public sealed class SettingsStore
{
    public SettingsStore(string filePath);
    public static string DefaultPath { get; }   // %LocalAppData%\VuloPods\settings.json
    public AppSettings Current { get; }
    public event Action<AppSettings>? Changed;
    public void Load();                 // fehlt/kaputt → Defaults; kaputte Datei wird nach settings.json.bad verschoben und geloggt
    public void Save(AppSettings next); // normalisiert, schreibt atomar (tmp + File.Move overwrite), setzt Current, feuert Changed nur bei Änderung
}
```

JSON über `System.Text.Json`, Enums als Strings (`JsonStringEnumConverter`), eingerückt,
unbekannte Felder ignoriert, fehlende Felder = Default.

`LowBatteryPolicy`: Konstruktor `LowBatteryPolicy(int threshold = 20)`, Property
`Threshold` statt Konstante; Hysterese-Regel unverändert, aber gegen den Instanzwert.
Bei Schwellenänderung erzeugt die App eine neue Instanz.

### App

`SettingsWindow.xaml` (normales Fenster, 420×auto, `ResizeMode=NoResize`,
`WindowStartupLocation=CenterScreen`, Titel „VuloPods – Einstellungen“, Icon = App-Icon,
nur eine Instanz gleichzeitig; bei erneutem Aufruf `Activate()`):

| Gruppe | Steuerelement |
|---|---|
| Allgemein | Checkbox „Mit Windows starten“ (direkt `AutostartManager`) |
| Popup | Checkbox „Beim Öffnen des Deckels anzeigen“; Slider „Anzeigedauer“ 3–15 s mit Wertanzeige |
| Wiedergabe | Checkbox „Pausieren, wenn ein AirPod herausgenommen wird“ |
| Akku | Checkbox „Warnung bei niedrigem Akku“; ComboBox Schwelle 10/15/…/50 % |
| Darstellung | ComboBox Tray-Icon „Logo“ / „Akku in Prozent“; ComboBox Design „Wie Windows“ / „Hell“ / „Dunkel“ |
| Info | Version, Link „GitHub“ → `https://github.com/mrvulo/VuloPods` |

Änderungen werden **sofort** übernommen und gespeichert (kein OK/Abbrechen). Das Fenster
folgt dem gewählten Design über dieselben Theme-Dictionaries (neue Schlüssel
`WindowBackground`, `WindowText`, `ControlBackground`, `ControlBorder` in `Dark.xaml`/`Light.xaml`).

Wirkung in `App` (Handler auf `SettingsStore.Changed`):

- `PopupOnLidOpen` false → `LidOpened` zeigt kein Popup (Tray-Klick weiterhin)
- `PopupSeconds` → `PopupWindow.AutoHideDelay` wird Instanz-Property, beim nächsten Anzeigen wirksam
- `AutoPause` false → `EarStateChanged`/`DeviceAppeared` rufen `AutoPausePolicy.OnEarState` nicht auf; beim Ausschalten `Reset()`
- `LowBatteryWarning` false → keine Toasts; Schwelle → neue `LowBatteryPolicy`
- `TrayIcon` → Icon sofort neu setzen (Abschnitt 4)
- `Theme` → `ApplyTheme()` mit `ThemeMode`; bei `System` wie bisher Registry plus `UserPreferenceChanged`

Tray-Menü bekommt „Einstellungen…“. Doppelklick aufs Tray-Icon öffnet ebenfalls die Einstellungen.

## 3. Verbinden / Trennen

Treiberfrei und ohne Adminrechte über die Bluetooth-Audio-„One-Shot“-Properties des
KS-Filters, denselben Weg wie das Windows-Soundpanel (Referenzen: ToothTray, BSD-2;
PodBridge, Apache-2.0; Konstanten aus dem Windows SDK `ksmedia.h`, `devicetopology.h`,
`mmdeviceapi.h` – kein fremder Code wird übernommen).

### Core: `src/VuloPods.Core/Platform/BluetoothAudioConnector.cs`

```csharp
public sealed record PairedAudioDevice(string Name, string ContainerId, bool IsConnected, IReadOnlyList<string> FilterIds);

public static class BluetoothAudioConnector
{
    public static IReadOnlyList<PairedAudioDevice> FindAppleAudioDevices();
    public static bool Connect(PairedAudioDevice device);     // KSPROPERTY_ONESHOT_RECONNECT an alle FilterIds
    public static bool Disconnect(PairedAudioDevice device);  // KSPROPERTY_ONESHOT_DISCONNECT an alle FilterIds
}
```

- COM-Interop in `src/VuloPods.Core/Platform/Interop/CoreAudioInterop.cs` (internal):
  `MMDeviceEnumerator` (CLSID `BCDE0395-E52F-467C-8E3D-C4579291692E`),
  `IMMDeviceEnumerator` `A95664D2-9614-4F35-A746-DE8DB63617E6`,
  `IMMDeviceCollection` `0BD7A1BE-7A1A-44DB-8397-CC5392387B5E`,
  `IMMDevice` `D666063F-1587-4E43-81F1-B948E807363F`, `IPropertyStore`,
  `IDeviceTopology` `2A07407E-6497-4A18-9787-32F79BD0D98F`,
  `IConnector` `9C2C4058-23F5-41DE-877A-DF3AF236A09E`,
  `IKsControl` `28F54685-06FD-11D2-B27A-00A0C9223196`;
  `KSPROPSETID_BtAudio` `7FA06C40-B8F6-4C7E-8556-E8C33A12E54D`,
  `ONESHOT_RECONNECT = 0`, `ONESHOT_DISCONNECT = 1`, `KSPROPERTY_TYPE_GET = 1`,
  `KSPROPERTY` = `{ Guid Set; uint Id; uint Flags; }` (24 Byte). Vtable-Reihenfolge exakt
  nach SDK-Header, unbenutzte Slots als Platzhalter.
- Ablauf `FindAppleAudioDevices`: `EnumAudioEndpoints(eAll, ACTIVE | UNPLUGGED)`; pro
  Endpunkt `IDeviceTopology` → alle Connectors → `GetDeviceIdConnectedTo` (PreserveSig,
  `E_NOTFOUND` überspringen) → nur IDs, die mit `{2}.\\?\bth` beginnen (A2DP und
  Freisprech) → Filter-ID merken. Gruppieren nach `PKEY_Device_ContainerId`
  (`{8c7ed206-3f8a-4827-b3ab-ae9e1faefc6c},2`) des Endpunkts. Name =
  `PKEY_DeviceInterface_FriendlyName` (`{026e516e-b814-414b-83cd-856d6fef4822},2`).
  Nur Gruppen behalten, deren Name „AirPods“ oder „Beats“ enthält (ohne Groß/Klein).
  `IsConnected` = mindestens ein Endpunkt der Gruppe `DEVICE_STATE_ACTIVE`.
- `Connect`/`Disconnect`: Filter-Gerät per `GetDevice(filterId)` holen, `Activate(IKsControl)`,
  `KsProperty(ref prop, 24, IntPtr.Zero, 0, out _)` pro eindeutiger Filter-ID. Rückgabe
  true, wenn mindestens ein Aufruf `S_OK` lieferte. S_OK heißt nur „angenommen“; der
  Aufrufer prüft den Zustand später neu.
- Alle COM-Objekte werden per `Marshal.ReleaseComObject` freigegeben. Aufrufe laufen auf
  einem Threadpool-Thread (MTA), nie auf dem UI-Thread. Jede Ausnahme wird geloggt;
  die Methoden werfen nie (leere Liste / false).

### App

- Tray-Menü wird beim Öffnen (`ContextMenu.Opened`) aktualisiert: `FindAppleAudioDevices`
  im Hintergrund, Ergebnis auf dem UI-Thread einsetzen.
  - Kein Gerät: deaktivierter Eintrag „Keine gekoppelten AirPods“.
  - Ein Gerät: Eintrag „<Name> trennen“ bzw. „<Name> verbinden“.
  - Mehrere: Untermenü „Verbinden / Trennen“ mit einem Eintrag pro Gerät, verbundene mit Haken.
- Klick: `Connect`/`Disconnect` im Hintergrund, nach 4 s erneut abfragen und das Ergebnis
  loggen. Schlägt es fehl (immer noch alter Zustand), Toast „Verbinden fehlgeschlagen“ /
  „Trennen fehlgeschlagen“.

### Grenzen

- Geräte, deren Name weder „AirPods“ noch „Beats“ enthält (umbenannt), erscheinen nicht.
- Verbinden scheitert, wenn die AirPods gerade mit einem anderen Gerät verbunden sind und
  dieses sie nicht freigibt; das ist Windows-/Apple-Verhalten.

## 4. Akku-Prozent im Tray-Icon

Core, reine Logik, `src/VuloPods.Core/Models/TrayBadge.cs`:

```csharp
public enum BadgeLevel { Normal, Low, Charging }
public sealed record TrayBadge(string Text, BadgeLevel Level);
public static class TrayBadges
{
    public static TrayBadge? Compute(AirPodsAdvertisement? adv, int lowThreshold);
}
```

Regel: Wert = Minimum der bekannten Werte von links/rechts; sind beide unbekannt, der
Case-Wert; ist alles unbekannt oder `adv` null → `null` (App zeigt das Logo). Text = Zahl
ohne Prozentzeichen, 100 bleibt „100“. Level: `Charging`, wenn der gewählte Teil lädt
(bei Pods: einer der beiden Pods, deren Wert das Minimum ist, lädt), sonst `Low`, wenn
Wert ≤ `lowThreshold`, sonst `Normal`.

App, `src/VuloPods.App/TrayIconRenderer.cs`:
`static System.Drawing.Icon Render(TrayBadge badge, bool lightTaskbar, int sizePx)`.
Transparenter Hintergrund, Zahl fett zentriert, Schrift „Segoe UI“, Größe so gewählt, dass
der Text 95 % der Breite nicht überschreitet (dreistellig schmaler). Farben: Normal =
weiß auf dunkler / `#1E1E22` auf heller Taskleiste; Low = `#FF453A`; Charging = `#30D158`.
Kleiner Unterstrich-Balken in Goldton `#D4A017` (2 px hoch, volle Breite) als
Wiedererkennung. Icon über `Icon.FromHandle(bitmap.GetHicon())` erzeugen und das HICON
nach dem Klonen per `DestroyIcon` freigeben, damit bei jedem Update kein GDI-Handle leakt.
`sizePx` = `GetSystemMetricsForDpi(SM_CXSMICON, dpi)` des primären Monitors.

`WindowsTheme.IsTaskbarLight()` (neu, Core): Registry
`HKCU\...\Themes\Personalize` Wert `SystemUsesLightTheme` (fehlend → false).

`TrayService.SetIcon(System.Drawing.Icon? icon)`: null → Logo aus `Assets/tray.ico`.
Aktualisierung bei `StateChanged`, `DeviceAppeared`, `DeviceLost`, Einstellungs- und
Theme-Wechsel; nur neu zeichnen, wenn sich Badge, Taskleisten-Theme oder Größe geändert hat.

## 5. Release-Paket

`scripts/package.ps1 [-Version <x.y.z>]`: liest die Version aus `Directory.Build.props`,
wenn nicht angegeben. Baut zwei Artefakte nach `artifacts/` (in `.gitignore`):

- `VuloPods-<ver>-win-x64.zip`: self-contained Single-File
  (`-r win-x64 --self-contained true -p:PublishSingleFile=true
  -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true`),
  enthält `VuloPods.exe`, `LICENSE`, `README.md`. Läuft ohne installiertes .NET.
- `SHA256SUMS.txt` mit dem Hash der ZIP.

Releases auf GitHub: Tag `v<ver>`, Titel `VuloPods <ver>`, Notizen aus
`docs/releases/<ver>.md` (deutsch, Abschnitte „Neu“, „Verbessert“, „Hinweise“), Assets
ZIP + SHA256SUMS. Nachträglich auch für `v1.1.0`.

`Directory.Build.props`: `<Version>1.2.0</Version>`.
