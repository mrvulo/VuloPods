# VuloPods v1.1 – Design

Datum: 2026-10-19
Basis: v1 (`2026-09-13-vulopods-v1-design.md`), alle Regeln daraus gelten weiter.
Umfang: sechs kleine, treiberfreie Verbesserungen plus Lizenz. Keine Einstellungs-UI,
kein Verbinden/Trennen, kein Installer (das ist v1.2).

## 1. Autostart

- Tray-Menüpunkt „Mit Windows starten“, ankreuzbar (`IsCheckable`), Zustand aus der Registry.
- Core: `static class AutostartManager` in `VuloPods.Core/System/AutostartManager.cs`:
  `bool IsEnabled()`, `void SetEnabled(bool enabled)`. Schlüssel
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, Wert `VuloPods` =
  `"<Pfad zur VuloPods.exe>"` (in Anführungszeichen, `Environment.ProcessPath`).
- Registry-Fehler werden geloggt, nie geworfen.

## 2. Akku-Warnung

- Core: `sealed class LowBatteryPolicy` in `VuloPods.Core/Battery/LowBatteryPolicy.cs`,
  reine Logik, testbar. Konstante `Threshold = 20` (Prozent).
  `IReadOnlyList<LowBatteryAlert> Evaluate(AirPodsAdvertisement adv)` gibt die neu
  auszulösenden Warnungen zurück. `record LowBatteryAlert(BatteryPart Part, int Percent)`,
  `enum BatteryPart { Left, Right, Case }`.
- Regel pro Teil: Warnung, wenn Wert bekannt, `<= 20`, nicht ladend, und das Teil zuvor
  **über** 20 lag oder noch nie bewertet wurde. Danach keine weitere Warnung für dieses
  Teil, bis es wieder über 20 gemessen wurde (Hysterese). `Reset()` löscht den Zustand
  (wird bei `DeviceLost` aufgerufen).
- App: Windows-Toast über das NuGet-Paket `Microsoft.Toolkit.Uwp.Notifications`
  (`ToastContentBuilder`, funktioniert unverpackt). Text:
  Titel `VuloPods`, Zeile `Linker AirPod: 20 %` / `Rechter AirPod: 10 %` / `Ladecase: 20 %`.
- Keine Toasts, während eine Vollbild-Anwendung im Vordergrund ist. App:
  `static class FullscreenDetector.IsFullscreenForeground()` per
  `GetForegroundWindow` + `GetWindowRect` + `MonitorFromWindow`: Vordergrundfenster
  deckt den gesamten Monitor ab und ist nicht die Shell (`Progman`/`WorkerW`) → true.
  Unterdrückte Warnungen werden nicht nachgeholt (Hysterese bleibt gesetzt); das ist
  bewusst einfach.

## 3. Popup ohne Fokusklau

- `PopupWindow`: `ShowActivated="False"`, kein `Activate()`, und in `OnSourceInitialized`
  per `SetWindowLong(GWL_EXSTYLE)` die Flags `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` setzen
  (`WS_EX_TOOLWINDOW` entfernt den Alt-Tab-Eintrag).
- „Klick daneben schließt“ kann nicht mehr über `Deactivated` laufen. Stattdessen ein
  globaler Low-Level-Maus-Hook (`SetWindowsHookEx(WH_MOUSE_LL)`), der nur installiert ist,
  solange das Popup sichtbar ist: jede Maustaste **außerhalb** des Popup-Rechtecks
  (Bildschirmkoordinaten, DPI-korrekt über `PresentationSource.CompositionTarget`)
  versteckt es sofort. Hook-Delegate als Feld halten (GC). App-Datei
  `VuloPods.App/Interop/MouseHook.cs` (`sealed class MouseHook : IDisposable`,
  Event `Action<int, int>? ButtonDown`).

## 4. Hell/Dunkel-Theme

- Core: `static class WindowsTheme` in `VuloPods.Core/System/WindowsTheme.cs`:
  `bool IsLight()` liest `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize`
  Wert `AppsUseLightTheme` (fehlend → dunkel).
- App: zwei `ResourceDictionary`-Dateien `Themes/Dark.xaml` und `Themes/Light.xaml` mit
  den Schlüsseln `PopupBackground`, `PopupText`, `PopupSubtle`, `BarBackground`,
  `BarForeground`, `AccentInEar`. `PopupWindow.xaml` referenziert nur noch
  `{DynamicResource ...}`. `App` lädt beim Start das passende Dictionary in
  `Application.Resources.MergedDictionaries` und tauscht es bei
  `SystemEvents.UserPreferenceChanged` (Kategorie `General`) aus.
- Dunkel: Hintergrund `#EE1E1E22`, Text `#FFFFFF`, Subtle `#BBBBBB`, Bar-Hintergrund
  `#33FFFFFF`, Bar `#4CD964`, Akzent `#4CD964`.
  Hell: Hintergrund `#F2FFFFFF`, Text `#1E1E22`, Subtle `#666666`, Bar-Hintergrund
  `#22000000`, Bar `#34C759`, Akzent `#34C759`.

## 5. Diagnose-Export

- Scanner hält immer (nicht nur mit `--dump`) einen Ringpuffer der letzten 200
  Apple-Rohpakete als Zeilen `"<Zeitstempel> <RSSI> dBm <Hex>"`:
  `IReadOnlyList<string> AirPodsScanner.RecentRawPackets` (thread-sicher kopiert).
- Core: `static class DiagnosticsExporter.Export(string logDirectory,
  IReadOnlyList<string> rawPackets, string targetZipPath)` in
  `VuloPods.Core/Logging/DiagnosticsExporter.cs`: packt `log.txt`, `log.1.txt` (falls
  vorhanden), `packets.txt` (Ringpuffer) und `system.txt` (OS-Version, App-Version,
  Bluetooth-Adapter-Name aus `BluetoothAdapter.GetDefaultAsync()`-Ergebnis, der Name
  wird vom Aufrufer übergeben: Signatur bekommt zusätzlich `string systemInfo`).
- Tray-Menüpunkt „Diagnose exportieren…“: Ziel
  `Desktop\VuloPods-Diagnose-yyyyMMdd-HHmmss.zip`, danach Explorer mit markierter Datei
  öffnen (`explorer.exe /select,"<pfad>"`).

## 6. Neue Modelle

`AirPodsModels.FromId` ergänzen (Big-Endian-Form wie bisher):
`0x3020`, `0x3620` → `AirPods5` („AirPods 5“), `0x1F20` → neuer Enum-Wert
`AirPodsMaxUsbC` („AirPods Max (USB-C)“), `0x1220` → `BeatsFitPro` („Beats Fit Pro“).
Quelle: AirPodsDesktop `AppleCP.cpp`, Stand 2026-09-19 (IDs sind Fakten, kein Code
übernommen).
